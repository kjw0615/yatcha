## 0. 설계 원칙

1. **규칙은 그대로.** `YachtRules.score / upper / bonus / total`을 수정 없이 호출한다. 3D 레이어는 `dice: Array[int]`(5개, 1~6)를 만들어 넘기는 역할만 한다.
2. **상태 가드도 그대로.** 현행 `main.gd`의 가드(`busy`, `finished`, `rolls`, `held`, `selected`)를 3D 버전에서도 같은 의미로 유지한다. 3D 연출 중에는 `busy = true`.
3. **물리가 결과의 원천.** 주사위 값은 물리 시뮬레이션이 멈춘 뒤 `get_top_face()`로 읽은 값이다. 연출용으로 값을 미리 정해 두고 물리를 맞추는 방식은 쓰지 않는다.
4. **모든 동작은 키보드만으로도 가능.** 마우스 드래그·컵 흔들기는 "손맛"이고, 같은 결과를 단축키로 얻을 수 있어야 한다.
5. **판정이 애매하면 플레이어에게 불리하게 처리하지 않는다.** 기울어짐·트레이 이탈은 굴림 횟수를 소모하지 않고 자동 보정한다(§2.4).

## 1. 시점 및 카메라

### 1.1 기본 배치 (월드 단위 = 미터, 주사위 한 변 0.016 m 대신 **게임 스케일 1.0 m**로 통일 권장)

```
         [ 킵 레일 (Keep Rail) — 슬롯 5칸 ]          ← 화면 상단 1/4
   ┌─────────────────────────────────────────┐
   │                                         │
   │        펠트 트레이 (롤 구역)             │      ← 화면 중앙
   │                                         │
   └─────────────────────────────────────────┘
  [컵]                                               ← 좌하단, 플레이어 쪽
```

- 트레이: 약 12 × 8 단위 사각형, 높이 1.2 단위 쿠션 벽(StaticBody3D). 주사위 1개 = 1 단위.
- 킵 레일: 트레이 먼 쪽(카메라 반대편) 벽 위에 5칸 홈. 플레이어 시점에서 "위쪽 선반"으로 읽힌다.
- 컵: 트레이 가까운 쪽 좌측 모서리 밖. 현재 플레이어 쪽에 놓인다(로컬 2인이므로 진영 교체 대신 **컵 색**만 플레이어 색으로 바꾼다).

### 1.2 카메라 상태 (Camera3D 1대 + 리그 Node3D, 상태 간 Tween 보간)

| 상태 | 언제 | 피치 / 거리 / FOV | 보간 | 의도 |
|---|---|---|---|---|
| `OVERVIEW` | 턴 시작, 굴리기 전 | 피치 −55°, 거리 16, FOV 40 | 0.6 s, ease-in-out | 트레이·컵·킵 레일이 한 화면에 |
| `SHAKE` | 컵을 잡고 흔드는 중 | 컵 쪽으로 2 단위 이동, 거리 14 | 0.25 s | 긴장감. 흔들기 강도에 비례해 미세 진동(≤0.04 단위, 최대 12 Hz) |
| `FOLLOW` | 주사위 투척 ~ 정지 | 주사위 무게중심을 lerp(0.08/프레임)로 추적, 피치 −60° | 연속 | 굴러가는 모습이 화면 밖으로 나가지 않게. 트레이 경계로 클램프 |
| `READ` | 모든 주사위 정지 | 피치 −78°(거의 탑뷰), 주사위 바운딩 박스에 맞춰 줌 | 0.45 s | 윗면 숫자를 한눈에 읽도록 |
| `SCORE` | 점수표에 포커스(호버/키보드) | READ 유지 + 화면 좌측 30% 쪽으로 평행이동 | 0.3 s | 우측 점수표에 가리지 않게 주사위를 왼쪽으로 |
| `RESULT` | 게임 종료 | 천천히 궤도 회전(6°/s) | — | 승패 화면 배경 |

규칙:
- **플레이어가 직접 카메라를 회전시키지 않는다**(기본). 고정 각도가 판독성과 조작 일관성에 유리하다. 옵션: 우클릭 드래그로 ±20° 요(yaw)만 허용, 놓으면 0.4 s에 원위치.
- 카메라 진동·이동을 끄는 **"움직임 줄이기"** 옵션: 켜면 `SHAKE` 진동·`FOLLOW` 추적·`RESULT` 회전을 끄고 `OVERVIEW` ↔ `READ` 컷 전환만 한다.
- 창 비율이 16:10보다 좁아지면(예: 4:3) 거리 +15%로 트레이가 잘리지 않게 보정.

## 2. 조작법

### 2.1 입력 매핑 요약

| 동작 | 마우스 | 키보드 | 게임패드(선택) |
|---|---|---|---|
| 컵 흔들기 → 굴리기 | 컵을 누른 채 드래그로 흔들고 놓기 | `Space` 누르고 있기 → 떼기 | `A` 길게 → 떼기 |
| 빠른 굴리기 | 컵 단순 클릭 | `Space` 짧게 탭(<0.15 s) | `A` 탭 |
| 킵 / 언킵 | 주사위 클릭, 또는 킵 레일로 드래그 | `1`~`5` (왼쪽→오른쪽 순서) | 십자키로 선택 + `X` |
| 전체 언킵 | 킵 레일 빈 곳 더블클릭 | `0` 또는 `Backspace` | `Y` |
| 족보 선택 | 점수표 칸 클릭 | `↑` `↓` (현재 플레이어 열에서 빈 칸만 이동) | 십자키 상하 |
| 기록 확정 | 확정 버튼 클릭 / 선택된 칸 더블클릭 | `Enter` | `A` (점수표 포커스 시) |
| 규칙 · 새 게임 | 상단 버튼 | `F1` · `Ctrl+R` | `Select` · — |

- `1`~`5` 번호는 **트레이 위 주사위의 화면 X좌표 순서**로 매긴다(정지 직후 재정렬). 각 주사위 위에 번호 배지를 작게 띄워 키보드 사용자를 돕는다(§3.4).
- 현행과 같은 가드: `rolls == 0`이면 킵 불가, `rolls >= 3`이면 굴리기 불가, 5개 모두 킵이면 굴리기 불가, `busy` 동안 모든 입력 무시(카메라 옵션 제외).

### 2.2 주사위 굴리기 (컵)

**흔들기 단계**
1. 컵을 누르는 순간(또는 `Space` 다운) 킵하지 않은 주사위가 컵 안으로 0.2 s 동안 빨려 들어간다(트윈, 물리 off). 카메라 → `SHAKE`.
2. 마우스 드래그: 컵이 커서를 따라 트레이 가장자리 높이에서 움직인다(이동 범위는 트레이 앞쪽 절반으로 클램프). 
3. **흔들기 에너지** `E` (0~1)를 누적한다.
   - 마우스: 프레임마다 커서 이동 거리(px)를 화면 높이로 정규화해 더하고, 방향이 바뀔 때 보너스 +0.05. 초당 0.35씩 감쇠.
   - 키보드: `Space`를 누르고 있는 동안 초당 +0.8 자동 증가(0.6 s면 최대 근처), 컵은 자동으로 좌우로 흔들리는 애니메이션.
4. `E`에 비례해 컵 안 덜그럭 소리 볼륨·빈도 증가(§4.1), 컵 테두리 링 게이지가 차오른다.

**놓기(투척) 단계**
- 버튼을 떼면 컵이 트레이 쪽으로 기울며 주사위를 쏟는다.
- 각 주사위에 `roll(impulse, torque)` 호출:
  - `impulse` 방향 = 트레이 중앙 쪽 + 마지막 드래그 방향(가중치 0.4), 크기 = `lerp(6, 14, E)`, 개별 ±15% 난수.
  - `torque` = 무작위 축 × `lerp(8, 20, E)`.
  - 시작 위치는 컵 입구 근처에서 서로 0.3 단위 이상 떨어지도록 지터.
- 빠른 굴리기(클릭/탭)는 `E = 0.5`로 고정해 바로 투척한다.
- **`E`는 연출 강도만 바꾼다.** 결과의 무작위성은 물리 + 난수 지터에서 오며, 실력으로 특정 눈을 노릴 수 있게 설계하지 않는다(공정성).

**정지 대기**
- 카메라 `FOLLOW`. 5개(굴린 것들) 모두 `stopped` 시그널이 오면 → §2.4 판정 → `READ` 전환 → `rolls += 1`, `busy = false`.
- 안전장치: 투척 후 **4.0 s** 지나도 멈추지 않은 주사위는 감쇠를 10배로 올리고, 5.0 s에 강제 정지 후 판정.

### 2.3 킵(Keep) / 롤(Roll) 인터랙션

**호버**
- 마우스가 킵 가능한 주사위 위에 있으면: 주사위가 0.15 단위 떠오르고(트윈 0.12 s), 외곽선(rim) 하이라이트 + 커서 손 모양. 바닥 그림자가 살짝 작아져 "떠 있음"을 표현.
- 킵 불가 상태(`rolls == 0`, `busy`)에서는 호버 반응 없음 — 반응이 없다는 것 자체가 "지금은 못 한다"는 신호.

**클릭 = 토글**
- 롤 구역 주사위 클릭 → 킵 레일의 **가장 왼쪽 빈 슬롯**으로 아치형 경로(높이 1.5 단위) 0.28 s 이동. 이동 중 윗면이 바뀌지 않도록 **현재 윗면을 유지한 채 요(yaw)만 정렬**해 놓는다. (Codex 구현: freeze 후 Tween, 회전은 윗면 축 유지.)
- 킵 레일 주사위 클릭 → 롤 구역의 원래 정지 위치로 되돌아간다(원래 위치를 기억). 다른 주사위가 그 자리에 없으므로 겹침 걱정 없음(굴림 사이에만 토글 가능).

**드래그**
- 주사위를 누른 채 4 px 이상 움직이면 드래그 모드: 주사위가 커서 아래 평면(높이 1.0)에 붙어 따라온다.
- 킵 레일 위로 가면 가장 가까운 슬롯이 밝아지고, 놓으면 그 슬롯에 들어간다(이미 차 있으면 서로 자리 교환).
- 롤 구역으로 놓으면 언킵, 놓은 위치에 내려놓는다(다른 주사위와 1.1 단위 이내면 밀어서 간격 확보).
- 킵 레일 안에서의 드래그로 순서 재배열 가능(점수엔 영향 없음, 정리용).

**굴릴 때**
- 킵된 주사위는 레일에 그대로, 물리 비활성(freeze). 컵에는 킵하지 않은 주사위만 들어간다.
- 턴 종료(기록 확정) 시 레일의 주사위가 트레이로 돌아가고 모든 킵 해제.

**값의 출처**
- `dice[i]`는 항상 각 주사위의 `get_top_face()`(롤 구역) 또는 킵 직전에 읽어둔 값(레일). 레일에 놓인 주사위는 윗면 유지 이동이므로 두 값은 일치해야 하며, 디버그 빌드에서 불일치 시 경고 출력.

### 2.4 판정 예외 처리 (슬립 / 기울어짐 / 이탈)

| 상황 | 감지 | 처리 | 굴림 횟수 |
|---|---|---|---|
| **기울어짐(cocked)** — 벽이나 다른 주사위에 기대 정지 | 윗면 축과 `Vector3.UP`의 내적 < **0.92** (약 23°) | ① 해당 주사위만 작은 임펄스(크기 2, 위쪽)로 "톡" 튕김, 최대 2회 ② 그래도 기울면 가장 가까운 면으로 0.2 s 회전 스냅 | 소모 안 함 |
| **슬립** — 아직 미끄러지는데 sleeping 판정 | `stopped` 후 0.3 s 동안 위치 변화 > 0.02 | `stopped` 취소, 대기 재개 | — |
| **트레이 이탈** — 벽을 넘거나 바닥 아래 | y < −2 또는 트레이 AABB 밖 | 그 주사위만 컵 위치에서 다시 떨어뜨림(같은 `E`) | 소모 안 함 |
| **주사위끼리 쌓임** | 다른 주사위 위에 정지(바닥 높이 + 0.6 이상) | 기울어짐과 동일 처리 | 소모 안 함 |

- 보정이 일어나면 HUD 상태줄에 짧게 "주사위를 다시 놓았습니다" 표시(1.5 s). 숨기지 않고 알려 준다.
- 내적 임계값 0.92와 시간 상수는 Codex의 `die_3d.gd`에서 `@export`로 노출해 튜닝 가능하게.

### 2.5 남은 굴림 횟수(3회) 표시

세 군데에 **같은 정보**를 다른 방식으로 보여 준다:
1. **컵 테두리의 점 3개** (월드 공간): 사용하면 하나씩 꺼진다(빛남 → 회색, 0.2 s). 시선이 컵에 있을 때 바로 보인다.
2. **HUD 굴리기 버튼 라벨**: `굴리기 · 2회 남음` (현행 문구 유지). 0회면 `굴리기 완료 · 족보를 선택하세요`.
3. **상단 단계 표시**: `ROUND 05 / 12 · 굴리기 ●●○` — 현행 `phase_label`의 숫자를 점 기호로 교체.

- 마지막 1회가 남으면 컵 점이 플레이어 색으로 천천히 맥동(1 Hz).
- 3회를 모두 쓰면 컵이 반투명(alpha 0.4)으로 물러나고 클릭되지 않는다. 시선을 점수표로 유도.

## 3. UI / HUD 레이아웃

### 3.1 화면 분할 (기준 1280 × 860, `stretch_mode = canvas_items` 유지)

```
┌──────────────────────────────────────────────────────────────────────┐
│ ① 턴 패널                                      ⑤ 메뉴 (규칙 · 새 게임) │
│ PLAYER 1의 차례  ROUND 05/12 · ●●○                                    │
│                                                ┌─────────────────────┐│
│                                                │ ② 점수표 (글래스)    ││
│            3D 트레이 · 킵 레일 · 컵             │  족보   P1   P2      ││
│            (화면 좌측 ~68%)                     │  에이스  3    —      ││
│                                                │  ...                ││
│                                                │  보너스 41/63 · +0   ││
│                                                │  합계   88   102     ││
│                                                └─────────────────────┘│
│ ③ 상태줄: 보관할 주사위를 고르거나 족보를 선택하세요.                    │
│ ④ 액션바: [ 굴리기 · 2회 남음 ]   [ 풀하우스 · 23점 기록 확정 ]  최근 기록│
└──────────────────────────────────────────────────────────────────────┘
```

- 3D 뷰는 전체 화면(SubViewport 불필요, Camera3D가 루트 뷰포트를 사용). HUD는 그 위 `CanvasLayer`(layer 1).
- 점수표 폭은 화면 폭의 30% (최소 340 px, 최대 420 px). 카메라 `SCORE` 상태의 평행이동량은 이 폭과 연동.

### 3.2 반응형 규칙

| 창 폭 | 배치 |
|---|---|
| ≥ 1100 px | 위 기본 배치(점수표 우측 고정) |
| 800 ~ 1099 px | 점수표를 접힌 탭으로. 우측 가장자리 "점수표 ▸" 탭, 굴림 완료 후 자동 펼침, 기록 후 자동 접힘 |
| < 800 px (세로형) | 점수표를 하단 시트로(화면 높이 45%). 3D 뷰는 상단, 카메라 거리 +20% |

- 점수표 열은 **현재 플레이어 열 강조**(밝은 배경 + 상단 플레이어 색 띠), 상대 열은 60% 불투명도.
- 빈 칸에는 현행처럼 **예상 점수**를 회색 숫자로, 기록된 칸은 흰색 굵게. 선택된 칸은 민트(`#76e5c0`) 배경.
- 0점 예상 칸을 선택하면 확정 버튼이 주황 테두리로 바뀌고 "0점으로 소진" 문구(현행 동작 유지).
- 칸 호버 시 툴팁 = `YachtRules.HINTS[i]` (현행 동일).

### 3.3 글래스모피즘 테마

| 토큰 | 값 | 용도 |
|---|---|---|
| `glass_fill` | `#0E1A26` alpha 0.55 | 패널 배경 |
| `glass_border` | `#FFFFFF` alpha 0.14, 1 px | 패널 외곽선 |
| `glass_highlight` | 위→아래 그라디언트 `#FFFFFF` alpha 0.08 → 0 | 패널 상단 반사광 |
| `blur_radius` | 화면 텍스처 LOD 2.5 (≈ 8 px 블러) | 패널 뒤 3D 장면 흐림 |
| `accent` | `#76E5C0` (현행 MINT) | 선택, 진행, 킵 |
| `text` / `muted` | `#EAF3F5` / `#8FA7B8` (현행) | 본문 / 보조 |
| `p1` / `p2` | `#76E5C0` / `#F2B56B` | 플레이어 색 (컵, 열 강조, 킵 슬롯 테두리) |
| `radius` | 16 px (패널), 12 px (칸·버튼) | |

- 구현: 패널마다 `ColorRect` + `canvas_item` 셰이더(`hint_screen_texture, filter_linear_mipmap`에서 `textureLod`로 샘플 → 틴트 → 테두리). 현재 렌더러 `gl_compatibility`에서도 동작하지만 **성능·품질을 Antigravity가 확인**하고, 문제 시 블러 없이 반투명 `StyleBoxFlat`로 폴백(토큰 값 동일).
- 3D 쪽도 같은 톤으로: 어두운 청록 펠트 트레이, 반사 약한 유리 질감 킵 레일, 따뜻한 상아색 주사위 + 짙은 남색 핍. 배경색은 현행 `default_clear_color (0.035, 0.065, 0.1)` 유지.
- 글자는 현행 테마 폰트·크기(17)를 기준으로, 점수표 숫자는 고정폭 숫자(tabular) 스타일.

### 3.4 월드 공간 UI (3D 위에 붙는 표시)

- **주사위 번호 배지** `1`~`5`: 정지 후 각 주사위 위 0.9 단위에 `Label3D`(빌보드, 작게, muted). 키보드 입력이 있었거나 설정에서 켰을 때만 표시.
- **킵 슬롯**: 빈 슬롯은 얇은 테두리, 찬 슬롯은 플레이어 색 테두리 + 슬롯 아래 작은 자물쇠 아이콘(색만으로 구분하지 않도록 **모양도** 다르게).
- **컵 굴림 점 3개**: §2.5.
- HUD와 월드 UI가 같은 정보를 보여 줄 때 문구·색이 일치해야 한다(검수 항목).

## 4. 사운드 · 햅틱 · 시각 피드백

### 4.1 사운드

| 이벤트 | 소리 | 구현 메모 |
|---|---|---|
| 컵 흔들기 | 덜그럭 루프 (주사위 수만큼 레이어) | 볼륨·재생 속도 = `E`에 비례(0.4→1.0 / 0.9→1.15). 킵 많을수록 가벼운 소리 |
| 투척 | 짧은 휙 + 쏟아지는 소리 | |
| 주사위 ↔ 펠트 바닥 | 둔탁한 "툭" | `contact_monitor`, `body_entered`에서 상대 속도로 볼륨 결정 |
| 주사위 ↔ 벽 | 나무 "딱" | 동일 |
| 주사위 ↔ 주사위 | 맑은 "딸깍" | 두 주사위 중 인스턴스 ID 작은 쪽만 재생(중복 방지) |
| 정지(전원) | 아주 작은 "틱" 1회 | 판독 시작 신호 |
| 킵 / 언킵 | 레일에 끼워지는 "찰칵" / 반대 피치 | |
| 기울어짐 보정 | 작은 "톡" | 숨기지 않고 들리게 |
| 족보 선택 / 확정 | 부드러운 클릭 / 상승 차임 | 점수 0이면 낮은 톤 |
| 특수 족보 | 라지 스트레이트·요트: 짧은 팡파르 | 굴림 직후 해당 족보가 **가능해졌을 때** 1회(기록 시 아님) |
| 게임 종료 | 승리 징글 | |

- 충돌음 규칙: 상대 속도 < 0.5 무음, 0.5~8을 볼륨 −24~0 dB로 매핑, 피치 ±6% 난수, **주사위당 60 ms 쿨다운**, 동시 재생 최대 8 보이스(`AudioStreamPlayer3D` 풀).
- 버스: `Master` ← `SFX`(물리음), `UI`, `Music`. 설정에서 각각 볼륨 조절.

### 4.2 햅틱

- 게임패드: `Input.start_joy_vibration` — 흔들기 중 약(0.1~0.3, `E` 비례), 투척 순간 중(0.5, 80 ms), 요트 성립 시 강(0.8, 250 ms).
- 모바일(향후): `Input.vibrate_handheld(30)` 투척 / `(15)` 킵.
- 설정에서 끌 수 있어야 한다.

### 4.3 시각 피드백

- **킵 상태는 색 + 위치 + 모양 3중 표시** (레일 위치, 플레이어 색 테두리, 자물쇠 아이콘). 색각 이상 사용자도 구분 가능해야 함.
- 투척 순간 컵 입구에 작은 먼지 파티클(펠트 보풀), 강한 충돌(속도 > 6) 시 접촉점에 미세한 링.
- 정지 후 판독 시 각 주사위 윗면이 0.25 s 살짝 빛나며 순서대로 숫자 팝업(Label3D, 0.06 s 간격) → HUD 점수표 예상치 갱신.
- 족보 성립 하이라이트: 점수표에서 현재 주사위로 0보다 큰 칸은 예상 점수가 민트색, 그중 최고점 칸에 작은 별표(추천 아님, "가능"만 표시 — 판단은 플레이어 몫).
- 요트 성립: 화면 가장자리 플레이어 색 비네트 펄스 1회 + 주사위 5개 동시 바운스(0.1 단위).
- 턴 전환: 컵이 상대 색으로 바뀌며 짧게 미끄러짐, 턴 패널 텍스트 크로스페이드.
- **움직임 줄이기** 옵션이 켜지면 파티클·비네트·바운스를 끄고 색 변화만 남긴다.

## 5. 상태 기계 (main_3d 통합용)

```
TURN_START ──(컵 누름/Space)──▶ SHAKING ──(놓기)──▶ ROLLING ──(전원 stopped)──▶ VALIDATING
     ▲                                                                            │ (기울어짐/이탈 보정, 0~2회)
     │                                                                            ▼
     │                                     ┌──────────── rolls < 3 ◀────────── SETTLED (rolls += 1)
     │                                     ▼                                      │
     │                              킵 토글 가능, 재굴림 가능                       │ 족보 선택
     │                                                                            ▼
     └────────(다음 플레이어, 킵 해제)──── COMMIT ◀──(Enter/확정)────────────── SELECTING
                                              │ 양쪽 12칸 완료
                                              ▼
                                           GAME_OVER
```

- `busy = true` 구간: SHAKING, ROLLING, VALIDATING, 킵 이동 트윈 중.
- SETTLED와 SELECTING은 같은 화면이다(족보 선택 후에도 굴림이 남았다면 다시 굴릴 수 있음, 이때 `selected = -1`로 리셋 — 현행 `roll_dice()` 동작과 동일).

## 7. 검수 기준 (Step 5에서 Claude가 확인할 항목)

1. 1,000회 자동 굴림 테스트에서 각 눈 빈도가 1/6 ± 1.5%p 이내(카이제곱 p > 0.01). 물리 편향 없음.
2. 판독 값과 화면에 보이는 윗면이 100% 일치(스크린샷 샘플 검사 30회).
3. 기울어짐·이탈 보정이 굴림 횟수를 소모하지 않음.
4. 마우스 없이 키보드만으로 한 판(24턴) 완주 가능.
5. 기존 `tests/test_game.gd`의 족보 경계값 테스트가 수정 없이 통과(규칙 무변경 증명).
6. 투척 → 판독 완료까지 평균 ≤ 3.0 s, 최대 5.5 s.
7. 1280×860, 1024×768, 800×1280(세로)에서 HUD가 3D 주사위를 가리지 않음.
8. 킵 상태를 색 없이(그레이스케일 스크린샷)도 구분 가능.
9. 움직임 줄이기 옵션에서 카메라 진동·추적·파티클이 꺼짐.

## 8. 미결정 사항 (사용자 확인 필요)

- 렌더러: 현행 `gl_compatibility` 유지(가벼움, 웹 호환) vs `forward_plus`(그림자·반사 품질). 기획은 둘 다 동작하도록 작성.
- 카메라 요 회전 옵션 포함 여부(기본 off 제안).
- 게임패드 지원을 1차 범위에 넣을지.
